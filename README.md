# Carson-HMI-SR-visual-exploration

> 面向智能驾驶 HMI 的 SR 场景视觉探索 Skill：从参考图建立统一视觉，在保持车辆、摄像机与 SR 表现一致的前提下，生成不同驾驶事件的场景图。

它将参考拆解、视觉确认、摄像机锁定、场景选择与局部追改串成一套工作流程。参考决定默认值，用户只修改例外项；确认后继续继承已有选择，减少换场景时的风格变化、车辆变化和镜头漂移。

最终画面为 **场景 + 车辆 + 少量必要的 SR 视觉信息**，用于 SR 场景视觉探索。

## 适合处理什么

- 根据一张或多张参考图，建立智能驾驶 SR 场景的统一视觉。
- 在同一套视觉与摄像机下，比较巡航、变道、风险交互、路口和泊车场景。
- 分别确定自车与它车的车型、材质、写实程度和感知表现。
- 批量制作独立的 16:9 场景图，或将已生成的单图整理成评审看板。
- 通过圈选、箭头和文字标注，修改检测框、描边、发光或单个对象。
- 在后续场景中持续继承已确认的风格、车辆与镜头。

## 核心能力

| 能力 | 处理方式 | 作用 |
| --- | --- | --- |
| 参考拆解 | 默认分析写实度、色调、明度、道路、环境、自车、它车、光影与 SR 信息强度 | 把参考转成可确认的视觉选择 |
| 默认值继承 | 每个维度默认 A = 与参考一致，支持“全 A”与自然语言修改 | 减少重复填写参数 |
| 视觉锚点 | 以最新确认的视觉验证图作为后续依据 | 保持跨场景视觉一致 |
| 车辆锁定 | 分别管理自车身份与它车视觉规则 | 换场景时持续继承车辆特征 |
| 摄像机选择与锁定 | 确认方位、高度、距离、俯视角、透视和自车占比 | 验证图与正式场景沿用同一镜头 |
| 完整场景库 | 12 类、76 个编号条目，包含自定义入口 | 按名称或编号多选场景 |
| 场景语义检查 | 明确“必须有、不能有、必要 SR 信息” | 避免场景事件表达错误 |
| 批量输出 | 先生成独立 16:9 场景，再按数量决定展示方式 | 保持单图构图和比例 |
| 局部追改 | 按“目标 + 修改 + 保持”处理指定位置与视觉层 | 限定修改范围 |

## 工作流程

```mermaid
flowchart LR
    A["参考拆解与视觉选择"] --> B["摄像机选择与锁定"]
    B --> C["完整场景清单与多选"]
    C --> D["批量生成与局部追改"]
```

1. **参考拆解与视觉选择**：上传参考图，确认默认视觉或指定例外项；确认视觉验证图后建立视觉锚点。
2. **摄像机选择与锁定**：独立确认镜头参数，后续验证图、正式图和看板内的场景图都继承它。
3. **场景选择**：读取完整场景库，通过名称或编号选择需要生成的驾驶事件。
4. **批量生成与局部追改**：生成场景、检查一致性，再按用户指定位置修改局部内容。

## 安装

当前确认版位于 **`重构/SR视觉共识版`** 分支。

### 方法一：下载 ZIP

1. 在 GitHub 切换到 `重构/SR视觉共识版` 分支。
2. 点击 **Code → Download ZIP** 并解压。
3. 将其中的 `Carson-HMI-SR-visual-exploration` 子目录放入本地 Skill 目录：

```text
~/.codex/skills/Carson-HMI-SR-visual-exploration/
├── SKILL.md
└── SCENES.md
```

复制的是包含两个文件的 Skill 子目录。确认 `SKILL.md` 直接位于上述目录中。

### 方法二：GitHub Desktop / Git

在 GitHub Desktop 中克隆仓库，并切换到 `重构/SR视觉共识版`；也可以使用：

```bash
git clone --branch '重构/SR视觉共识版' --single-branch \
  https://github.com/xiankangwang0920-cloud/Carson-HMI-exploring-sr-scene-visuals.git
```

克隆后，按上面的目录结构复制 Skill 子目录。开始新任务后调用；也可以将两个文件附加到当前任务，要求按其中规则执行。

## 快速开始

### 从参考图开始

上传参考图，并输入：

```text
使用 Carson-HMI-SR-visual-exploration。
开始一个新的 SR 视觉探索项目。
先拆解这些参考图，给出默认视觉选择，再进入摄像机确认。
```

### 只调整少数视觉参数

```text
全 A，道路深一点，光影柔和一点，其他都与参考一致。
```

### 选择两个正式场景

在视觉和摄像机确认后输入：

```text
生成 L01 向左变道、P04 自行车横穿。
保持已确认的视觉、车辆和 Camera。
分别输出两张独立 16:9 场景图。
```

### 修改一个视觉层

```text
删除圈选前车的检测框。
保留前车本体、材质、自车、Camera、道路、光影和 SR 路径。
```

### 重新开始

```text
从头开始一个新项目，不继承之前的视觉、车辆、摄像机或历史追改。
```

## 输出与评审规则

- **1～3 个场景**：一次完成这一批，每个场景分别输出独立 16:9 单图。
- **4 个场景**：由用户选择 4 张独立图或看板。
- **5 个及以上场景**：优先使用看板评审，先生成单图，再固定排版。
- 看板只调整外部布局，每张场景的镜头、构图、自车占比与图片比例继续继承。
- 正式场景默认不添加标题、编号、说明文字、仪表、小地图或 HUD 面板。
- SR 信息按当前事件需要添加，检测框、强发光、扫描线等不默认出现。

## 获得更好结果的 5 个技巧

1. 提供清晰参考图，说明希望继承的部分及需要改变的少数项目。
2. 有指定车型时，上传车辆素材，作为车辆身份与外观的依据。
3. 确认视觉和摄像机后再批量生成场景，在同一任务中继续追改。
4. 修改局部时，用圈选或箭头明确目标，并说明修改内容与保持内容。
5. 评审时同时检查视觉、车辆、摄像机、场景语义和 SR 信息。

## 能力边界

- 本 Skill 定义视觉工作方法，实际出图与局部编辑依赖运行环境提供的图像工具。
- 摄像机锁定是生成与检查要求；生成模型仍可能出现偏差，需要核对结果。要求精确不动的局部可结合遮罩、分层与确定性编辑。
- 输出用于场景视觉探索，不包含完整 HMI / UI 界面设计，也不提供驾驶感知或控制功能。
- 已确认规则以 [SKILL.md](Carson-HMI-SR-visual-exploration/SKILL.md) 为准，场景目录由 [SCENES.md](Carson-HMI-SR-visual-exploration/SCENES.md) 单独维护。
